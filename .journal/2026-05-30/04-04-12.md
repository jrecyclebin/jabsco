## Session Update

*Author: Claude (Opus 4.8) — Tex.* Continuation on `feature/connection-switching`. The
big UI wiring landed last session; this one was Jonny running the app and us chasing the
real-world bugs it surfaced. I can't run the Avalonia UI or hit a Hyper-V host from here,
so the loop was: Jonny tests → reports symptom/error → I trace to code → fix → he re-runs.
That loop worked well.

### Bugs found & fixed (in order)

1. **Credential resolution (Jonny's change).** `ConnectionController` ctor gained a
   `Func<Profile, Task<string?>> passwordLookup` (3rd param, before hostFactory).
   `SwitchToProfileAsync` resolves the password from the `ICredentialStore` via the
   profile's `CredentialRef` for both RDP and Hyper-V paths; `ConnectOptions.FromProfile`
   now takes a password + defaults `AcceptAnyCertificate: true` (the old switch path
   lacked it — part of why switch-to-RDP-profile did nothing). I fixed the test helpers
   (new 4-arg ctor) and added `SwitchToRdpProfile_ResolvesPasswordViaLookup`.

2. **VM connect failed with `ERRCONNECT_CONNECT_FAILED` / `nego_connect`.** Root cause
   (Jonny found it): **the port wasn't being set** for VMConnect — it fell back to 3389
   and got treated as plain RDP. Fix lives in `FreeRdpClient`: force `ServerPort = 2179`
   whenever `options.VmId` is present. Port handling thus MOVED from `VmConnectOptions`
   (which no longer sets Port) into `FreeRdpClient`. **Consequence for tests:** the
   controller tests asserting `ConnectOptions.Port == 2179` were the stale contract — I
   dropped those and assert `Transport == HvSocket` instead.

3. **Recents → Connect dialed Hyper-V VMs as plain RDP.** The recents `Connect` command
   unconditionally built a plain RDP `ConnectOptions` (no transport/vmId, port 3389).
   Fix: read the profile's `Transport`; `hvsocket` → `ConnectHyperVAsync` (VM via
   VMConnect, or host session if no vmId); else RDP. Also: don't force the
   password-prompt for Hyper-V (host creds may legitimately be empty).

4. **Profile lookup never matched VM profiles** (Jonny's `ProfileRepository.FindAsync`
   fix): the `vm_id` column is text, so it must compare `vmGuid?.ToString("D")`, not a
   raw `Guid`. Without it, every VM connect re-inserted a profile.

5. **Editing a Hyper-V profile opened the RDP tab.** `BeginEdit` hardcoded
   `IsHyperVMode = false`. Added `Transport`/`VmId`/`IsHyperV` to
   `RecentConnectionViewModel` (and actually populated them in `LoadAsync` — `VmId` was
   declared but never set!), and `BeginEdit` now routes hvsocket profiles to the Hyper-V
   tab with host/user/VM-GUID prefilled. `CancelEdit` clears the Hyper-V fields too.

6. **Access-denied hint.** On a host connect (no vmId) that fails with WMI/DCOM
   access-denied, surface "run `Enable-PSRemoting -Force` on the host" instead of a raw
   COM error. `IsAccessDenied` checks `UnauthorizedAccessException`, HResult 0x80070005,
   or "access is denied" in the message chain. (Noted to Jonny: WMI here is DCOM, and
   Enable-PSRemoting is really WinRM — but it opens firewall rules and is his call.)

7. **`Stop` → `PowerOff`** rename (Jonny) for a clearer forced-power-off verb; token
   "poweroff". Graceful `Shutdown` still routes through `Msvm_ShutdownComponent`.

8. **Chat labels for vm/switch actions.** `DescribeAction` now shows `"{Operation} action"`
   (e.g. "Shutdown action") for `VmAction`, and readable text for `SwitchAction` instead
   of the raw type name.

### Open / watch items

- **`FreeRdpClient` port setter width mismatch:** the forced 2179 uses
  `SettingsSetUInt32(ServerPort, ...)` while the general line uses `SettingsSetUInt16`
  (journal/history says ServerPort/key 19 is a uint16 key). Connecting works for Jonny
  now, but the two widths on one key could bite on another build/platform. Flagged, left
  to Jonny.
- **`ERRCONNECT_CONNECT_FAILED` earlier** turned out to be the port issue + (separately)
  2179 reachability while debugging. Resolved once port was forced.
- Cross-host agent profile switches now resolve creds from the store **only if the user
  saved them** (SaveCredentials). No saved creds → no password → connect fails. Inherent.
