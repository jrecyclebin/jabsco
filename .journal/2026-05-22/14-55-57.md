## Session Update

**Completed:**
- Fixed blank conversation history across prompts: `SessionViewModel` was newing up `AgentLoop` on every prompt, discarding prior context. Added `_conversationHistory: List<ConversationTurn>` to the VM, passed as `initialHistory`, captured back via `loop.History.ToList()` after each run.
- Restructured history types: old flat `ConversationTurn(Action, ToolResult, ToolUseId)` replaced with two-level model — `ToolTurn` (single within-run exchange) and `ConversationTurn(UserPrompt, IReadOnlyList<ToolTurn> Turns, FinalResponse?)`. `ProviderRequest` gained `CurrentTurns` for in-progress within-run turns.
- Rewrote `ClaudeProvider.BuildRequest` to correctly replay past rounds before the current prompt: `user[prompt] → assistant[tool_use] → user[tool_result] → ... → assistant[response]`, then current prompt + in-progress turns. Screenshots are stripped from history entirely.
- Preserved interrupted rounds (cancelled/budget-exceeded): `AgentLoop` now adds a partial `ConversationTurn` (with `FinalResponse: null`) after the loop exits if any turns completed. `BuildRequest` closes the user/assistant alternation gap with a synthetic `[Interrupted]` assistant message.
- Changed default `ControlMode` to `Observe`. Observe now allows interaction (`CanInteract`) when `IsAgentRunning == false`, blocking input only while the agent is active.
- Added then removed `DumpPayload` feature (env-var-gated file dump of LLM request JSON) per user request.

**Key files:**
- `src/Jabsco.Core/Providers/IComputerUseProvider.cs` — `ToolTurn`, `ConversationTurn`, `ProviderRequest` types
- `src/Jabsco.Core/Agent/AgentLoop.cs` — `currentTurns` tracking, round commit on `DoneAction` and loop exit
- `src/Jabsco.Core/Providers/Claude/ClaudeProvider.cs` — `BuildRequest` rewrite, helper methods `AssistantToolUse`, `UserToolResult`, `AssistantTextMessage`

**Observations:**
- Passing `currentTurns` by reference to `ProviderRequest` and `ConversationTurn` is safe here (list is never touched after storage), but it's a type system lie — `IReadOnlyList<ToolTurn>` wrapping a mutable `List<ToolTurn>`. Snapshotting with `[.. currentTurns]` at storage time would be cleaner; user deferred that.
- The `[Interrupted]` synthetic assistant message is load-bearing for API message alternation — without it, back-to-back `user` messages would cause a 400 from Anthropic.
