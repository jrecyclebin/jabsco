## Session Update

This was the founding session of Jabsco — a cross-platform .NET 10 tool that connects to machines over RDP and drives them with a Claude AI agent. Born at the 2026 AI Mini-Hackathon. Today we went from blank repo to a clean-building, 110-file, committed solution.

**The story of this session:**

We started by reading the Notion docs. Three pages: Design Doc, Project Structure, Research Log. The design was already sharp — Jonny had clearly thought hard about it. I flagged a few real issues:

1. **Conversation history memory** — no screenshot truncation/window strategy. Model hits context limits fast.
2. `--verbose-transcript` size estimate was wildly wrong (said ~3x, actual is massive — base64 screenshots per turn).
3. Two event type hierarchies (`AgentEvent` in Core + `EventDto` in Common).
4. FreeRDP native deps aren't just one DLL — it's a chain.
5. `ControlMode.Shared` — "last writer wins" is asking for trouble.
6. Build order had UI after persistence, which would be awkward.

Jonny took all of them. Decision batch that came out of it:
- Drop screenshots from history — only keep latest in `ProviderRequest`
- Screenshots not written to transcript (live stream only, `ScreenshotEvent` carries `byte[] PngBytes`)
- Coalesce event hierarchies — `AgentEvent` lives in `Jabsco.Common/Events/` with `[JsonDerivedType]` attrs, is its own wire format
- Drop Gemini (Claude only for now, `IComputerUseProvider` interface stays for future)
- Build full UI first, then make it work (cohesion over incremental)
- Drop `ControlMode.Shared`

All of those got updated in Notion too — Design Doc and Project Structure both patched in the same session.

**Then we started building.**

Git wasn't initialized when we first tried. Jonny sorted it. Then the actual work:

- Solution infrastructure (global.json, Directory.Build.props, .gitignore)
- All 6 projects scaffolded via `dotnet new`, added to solution, project refs wired
- NuGet packages added — Anthropic.SDK 5.10.0, SkiaSharp, Dapper, Microsoft.Data.Sqlite, StreamJsonRpc, System.CommandLine 3.0 preview, Avalonia 12 + CommunityToolkit.Mvvm, PowerShellStandard.Library, etc.

Key discovery mid-build: **Anthropic.SDK 5.10.0 has no native computer-use support.** The `Tool` class only has Name/Description/InputSchema — no `Type` field, no `computer_20241022`. So `ClaudeProvider` uses raw `HttpClient` with the beta header and hand-rolled JSON. That's actually fine — it keeps us in full control of the request shape.

Two cs-coder agents wrote the bulk of the source files in parallel:
- Agent 1: `Jabsco.Common` + `Jabsco.Core` (all types, FreeRDP P/Invoke, AgentLoop, ClaudeProvider, persistence, credentials, transcripts, platform services)
- Agent 2: `Jabsco.Cli`, `Jabsco.Daemon`, `Jabsco.PowerShell` scaffolds

Then a third agent wrote the full Avalonia UI (it found the template was using CommunityToolkit.Mvvm 8.x not ReactiveUI — adapted accordingly).

**Compilation gauntlet:**
- `LibraryImport` needs `AllowUnsafeBlocks` → added to Core csproj
- `NewJabscoSessionCmdlet.Host` hides `PSCmdlet.Host` → renamed to `HostName`
- `yield return` inside `catch` clause in `AgentLoop` → refactored to local variable pattern
- `ProtectedData` (DPAPI) needs `System.Security.Cryptography.ProtectedData` package → added
- `System.CommandLine` 3.0 API completely different from 2.x — `AddCommand/AddOption/SetHandler` all gone, replaced by `command.Add()` + `command.SetAction(parseResult => ...)` + `parseResult.GetValue(opt)`
- Missing `using Microsoft.Extensions.Hosting` / `using Microsoft.Extensions.DependencyInjection` in daemon
- `Argument<T>` 2-arg constructor gone in SCL 3.0 → use property initializer for Description

Clean build. One commit: 110 files, 3963 insertions.

**The big open item:**

`FreeRdpClient.cs` has clear TODO markers in `CaptureFramebuffer()` and `GetInputPtr()`. The FreeRDP 3.x struct offsets for `rdpContext` (where `input` and `gdi` live) need to be verified against the actual installed headers. This is the single gate between "compiling skeleton" and "actually driving Notepad." Once we have `libfreerdp3-dev` headers in hand, the offset lookups are straightforward — we're looking at maybe 2–3 struct field positions.

**What's next:**

1. **Verify FreeRDP 3.x struct offsets** — check `/usr/include/freerdp3/` or equivalent, nail down `rdpContext.input`, `rdpContext.update`, `rdpGdi.primary_buffer`, `rdpGdi.width/height`. Fill in the TODOs in `FreeRdpClient.cs`.
2. **Smoke test** — write a one-off test that connects to a VM, takes a screenshot, saves it to disk. Prove the P/Invoke layer works before wiring in Claude.
3. **AgentLoop integration** — once screenshot works, wire up `ClaudeProvider` and run a real prompt against a VM.
4. **UI wiring** — connect `SessionViewModel.CurrentFrame` to live `ScreenshotEvent` bytes so the framebuffer actually shows something.
5. **MEL version conflict** — Avalonia pulls in MEL 8.x vs our Core on 10.x. Currently just a warning but worth resolving by upgrading Avalonia's transitive deps or pinning in `Directory.Packages.props`.

Good session. We went from zero to a clean scaffold with real architecture and a real plan. The hard part is next — making the FreeRDP P/Invoke actually sing.
