## Session Update

Third session on Jabsco. Picked up from the working smoke test (full RDP screenshot confirmed) and wired everything up to the real UI, then fixed the Claude API integration.

**FreeRDP P/Invoke fixes (from previous session's smoke test):**
- `ServerPort` key is UINT32 (not UINT16) — fixed
- SkiaSharp Linux native assets need `SkiaSharp.NativeAssets.Linux` package to deploy in debug mode (only deploys with a RID specified otherwise)
- Hostname resolution: Windows machine names (`DESKTOP-AEJ51QF`) need to be on the same network. mDNS/NetBIOS don't resolve from Linux without Samba.

**Live UI wiring:**
Wired `ConnectionPanelViewModel` → `FreeRdpClient` → `SessionViewModel` → live framebuffer loop + agent. Key design:
- `ConnectionPanelViewModel` holds `MainWindowViewModel` ref; `ConnectToAsync` creates client, connects, creates `SessionViewModel`, calls `AddSession`
- `SessionViewModel` owns the `FreeRdpClient` + runs framebuffer polling loop at 100ms via background task dispatching `CurrentFrame` to UI thread
- `SendPromptAsync` creates `ClaudeProvider` + `AgentLoop`, streams events into `ChatItems` + `OverlayItems`
- `StopAgentCommand` cancels agent CTS
- `DisconnectCommand` stops loops, disconnects, fires `CloseTab` callback
- `AutoApproveSink` (inner class) auto-approves all tool actions for demo
- `Action? CloseTab` callback pattern instead of events to avoid circular refs

**Computer-use API fix — the big one:**
The 400 error was that `computer_20241022` + `computer-use-2024-10-22` is Claude 3.x only. Claude 4.x has two new versions:
- `computer_20251124` + `computer-use-2025-11-24` → Opus 4.7, Opus 4.6, Sonnet 4.6, Opus 4.5
- `computer_20250124` + `computer-use-2025-01-24` → Sonnet 4.5, Haiku 4.5, Opus 4.1, older

Fixed by deriving tool type + beta header from model string in `ClaudeProvider`. The `UsesNewComputerTool(model)` check covers the Claude 4.x top tier. Will need updating when new model versions ship.

**Technical notes for next session:**
- `FramebufferControl.cs` is a pure rendering control. To add input routing (Manual mode), add `PointerPressed`/`PointerMoved`/`KeyDown` handlers that call `SessionViewModel.MouseClickAsync` etc.
- The `RdpOverlayControl` has both an `Items` observable collection (for ClickRing/TargetBox items) AND a `_cursorTrail` queue (populated via `UpdateCursorPosition`). Currently only Items is wired. To wire the cursor trail, need a reference to the control from `SessionViewModel`, or better: add cursor position to `OverlayItems` using `OverlayKind.CursorTrail`.
- Actually, looking at `RdpOverlayControl.cs` — the `CursorTrail` kind is rendered separately via `_cursorTrail` queue, not from `Items`. The `Items` collection only handles `ClickRing` and `TargetBox`. So `CursorTrail` items added to `OverlayItems` from `SessionViewModel` won't render. Either use `UpdateCursorPosition` directly (needs control ref), or change the render logic to handle `CursorTrail` from `Items` too.
