### Shipped

`ConnectionController` (`src/Jabsco.Core/Sessions/ConnectionController.cs`) — the four-state
machine beneath a session. The nice part: **`Kind` is a pure function of two refs**, no
stored state field:

```csharp
public ConnectionKind Kind => (HasScreen, HasVmHost) switch {
    (false, false) => ConnectionKind.Disconnected,
    (true,  false) => ConnectionKind.Rdp,
    (false, true ) => ConnectionKind.VmHost,
    (true,  true ) => ConnectionKind.Vm,
};
```

Seams `IRdpConnector` + `IProfileDirectory` (+ a `Func<HostConnection,IVmHost>` host factory)
keep the FreeRDP/WMI lifecycle injectable, so the whole machine is unit-tested with fakes.
11 tests; full suite 74/74.

### The pivot: a host is a profile

After the first commit I flagged a dead end — once you `switch` to a plain profile, the host
context was nulled and `switch` had no way to target a host, so no RDP→host round-trip. Jonny:
that's because we skipped work — **VM hosts should be profiles, and so should direct-VM
connections.** The `profiles` table already has `vm_id` and `name` for exactly this (`host` =
the Hyper-V host's address; `name` = the VM's name).

Asked the one genuinely ambiguous question (how to tell a host-management profile from a
plain RDP profile, since both have `vm_id = null`). Jonny picked the transport-based encoding:

| transport | vm_id | → state |
|---|---|---|
| `tcp` | null | RDP (screen only) |
| `hvsocket` | `<guid>` | VM (screen + host, via VMConnect) |
| `hvsocket` | null | VM host (host, no screen) |

Refactored: dropped the `initialHost` constructor; **`SwitchToProfileAsync` is now the single
entry point** and classifies the profile to land in any of the four states. This makes
switching re-acquire a host (RDP → host profile → VM host) — dead end gone, added a test for
exactly that round-trip. `SwitchToVmAsync(vmId)` stays for "jump to another VM on the current
host" (model picks a GUID off the observation list).

### Deferred (on the record)

- **Credential resolution.** Profiles store `CredentialRef`, not passwords. Controller passes
  `profile.Username` + null password into `HostConnection`. A resolver must slot in before
  remote WMI / VMConnect work for real. Kept out of the state machine on purpose — orthogonal.
- **UI save-on-connect.** Connecting to a host/VM in the UI must now *save a profile* with the
  `hvsocket`/`vm_id` encoding. New Phase-1 task; not built yet.

### Next

### Collaboration note

Flagging the dead end in plain language ("here's a limitation I just built in") was the right
move — it surfaced that *I* was missing context (hosts-as-profiles), not that the design was
stuck. Jonny fixed it with one sentence and the schema got simpler, not more complex. When a
limitation feels unfortunate, say so out loud; it often means a missing requirement, not a
hard constraint.
