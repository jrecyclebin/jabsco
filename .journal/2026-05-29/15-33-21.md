## Session Update

Tex here. Long, satisfying haul on jabsco's screenshot/context handling. Branch: `feature/model-managed-strategy`.

### The story
Started simple: Jonny wanted a third `ModelStrategy`, **ModelManaged** — a screenshot after every user message and every screenshot tool call, *that's it*. Then the twist on retention: not a sliding window but a **25-turn sawtooth** — keep every screenshot, prune to the latest 3 each time 25 turns pass. Smart cache play: the prompt prefix stays byte-stable between prunes so the cache keeps hitting. And `wait` does NOT yield a screenshot (only the literal screenshot action does).

Mid-build, a linter/edit pass mangled `BuildMessages` into a half-merged, non-compiling state that also silently changed CacheAware. I stopped and flagged it rather than guessing. Jonny chose **"Unify, CacheAware changes"** — so all three strategies now share one points-based pipeline. Got it compiling, tested, committed.

Then the good architectural arc, driven by Jonny's instincts:
1. **Extract `ScreenshotPlan`** (provider-agnostic) so Gemini gets the strategies too and the logic leaves ClaudeProvider.
2. **Memory**: AgentLoop only stamps turns the strategy can use (`Records`) and frees screenshots once pruned for good (pruning is monotonic — dropped is never wanted again).
3. Jonny's sharp catch: *"if AgentLoop already prunes, why do providers re-run retention? Just check presence."* He was right. Refactored to **presence-based** providers: `ScreenshotPlan.Retained` returns kept keys (AgentLoop prunes with it), providers attach whatever screenshot survives on a turn/round, and cache_control (Anthropic-specific) moved into ClaudeProvider as `CacheBreakpoints`. Killed dead `ProviderRequest.ScreenshotPng`.
4. Default flipped to **CacheAware for everything**.
5. Jonny simplified the finalize prune: null `promptScreenshot` in place so the pruned value flows into both the request and the stored round. I reviewed it — functionally correct but the `??=` re-captured the prompt after nulling (a latent footgun resting on monotonic pruning). Fixed with `if (step == 1)` capture. Committed `21f03f9`.

### NEXT — OpenAI-compatible provider (was mid-write, interrupted)
Building a Chat Completions provider (key + base URL). Design is fully worked out:
- **No native computer tool** → expose one `computer` function (action enum + coordinate/start_coordinate/text/scroll_direction/scroll_amount/duration). **Pixel coords, no normalization** (model reasons over the actual image, unlike Gemini's 0–999).
- **Presence-based like Gemini, no cache** (OpenAI auto-caches).
- Key constraint: `tool` messages can't hold images → emit assistant `tool_calls` → `tool` result text → then a **`user` message carrying the resulting screenshot**.
- ParseResponse: `choices[0].message.tool_calls[0].function.arguments` (JSON string) → AgentAction; no tool_calls → `DoneAction(content)`; capture `reasoning_content`/`reasoning` as Thinking; usage from `prompt_tokens`/`completion_tokens`/`prompt_tokens_details.cached_tokens`.
