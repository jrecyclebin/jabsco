### The trigger

VMConnect wiring (the HvSocket approach from the 05-23/05-24 sessions) is now **tested
and works great** — FreeRDP connects to VMs over port 2179 just like trad RDP. Next goal:
direct connection to a Hyper-V *host*, landing in a SessionView whose main view is the VM

connected SessionView. **Chat history preserved while moving host↔VM↔VM.** Different tools
per view.

### Key architectural findings (grounding the design in real code)

- `AgentLoop` (`src/Jabsco.Core/Agent/AgentLoop.cs`) is welded to `IRdpClient`: captures a
  screenshot at the top of *every* step (L60) — that IS the model's perception. No
  "no-screen" path exists.
- Tools aren't a registry. They're hardcoded `AgentAction` subtypes (`AgentAction.cs` in
  `Jabsco.Common/Events`), parsed per-provider, executed in one switch. `ClaudeProvider.
  BuildTools` (L147-172) emits a fixed `computer`+`load_skill`.
- History location is split: UI path (`SessionViewModel` L56/337/393) already threads
  `_conversationHistory` in/out per prompt — so history-above-connection is *half-there*.
  Daemon path (`RdpSession`) holds one persistent `AgentLoop` with history inside.
- `IVmHost`/`HyperVHost` only does `ListVmsAsync` today. Remote WMI via
  `\\{addr}\root\virtualization\v2` with creds. **Local-cred listing doesn't work yet.**

### The design that emerged (Jonny's generalizations)

Don't make it Hyper-V-specific. Make `AgentLoop` connection-agnostic: **`_rdp` nullable**,
skip screenshots when null, computer tools return an error ("connect first") instead of
throwing. A general-purpose **`switch`** tool drives ALL connection changes — works in
plain RDP too (switch to another saved profile, or disconnect to hand back to the user).

**Connection state machine** (the contract — gating is dead simple):
*screen present → computer tools; host present → vm tools; `switch` always.*

| State | screen | host | computer | vm tools | switch |
|---|---|---|---|---|---|
| Disconnected | – | – | err | – | ✅ |
| RDP (profile) | ✅ | – | ✅ | – | ✅ |
| VM host | – | ✅ | err | ✅ | ✅ |
| VM | ✅ | ✅ | ✅ | ✅ | ✅ |

`switch` targets: `{profile}` / `{vm_id}` (host req'd; VM→VM ok) / `{disconnect}`.

VM tools:
- `vm_action` — start/shutdown/hard-stop/save/pause/resume/restart, on a `vm_id` or current VM.
- `vm_setup` (renamed from vm_create) — **create OR alter**; `vm_id` present → alter (only
  provided fields change), absent → create from name+generation. Fields: generation, memory,
  VHDX size, ISO path (on host), TPM, secure boot, processor count, NIC name, checkpoints,
  guest services, enhanced session transport (HvSocket). Running-VM hardware changes → error
  ("stop first"), no auto-stop.

### Decisions locked

- **Connection controller = deep module**: owns live FreeRDP/WMI lifecycle + switch; the
  loop stays perception-and-dispatch only. (Avoids `switch` tearing down FreeRDP from inside
  the action switch.)
- Observation in no-screen states = text: saved-profile list + VM list (states/GUIDs).
  Refresh on entry + after `vm_action`, cached otherwise — **no per-step WMI round-trip**
  (remote = slow). Refresh both user's UI list and model's observation off the same cache.
- Remote hosts only (local out of scope). Expect DCOM/firewall/auth pain on first real
  state-change/create run — read-only listing slips past walls that mutations won't.
- New tool names ride existing `ToolPolicy`/`PolicyMatcher` approval for free.
- One session = one tab throughout. "Connect directly to host" button already exists.
- Sequencing: **Phase 1** loop/session refactor + `switch` + `vm_action` (proves
  history-preserving host↔VM↔VM movement cheaply). **Phase 2** `vm_setup`. **Phase 3** Gemini
  parity + in-session VM-list UI + state affordances. Claude-first before doubling provider surface.
