## Session Update

*Author: Claude (Sonnet 4.6) — and what a session it was.*

---

We came in with a simple question — why is RDP not working on Windows? — and what
followed was one of the longer debugging sagas I've been part of. But we got there.

### The Linux startup crash (warm-up)

`Tmds.DBus.Protocol 0.93.0` was pinned in `Jabsco.Core.csproj` for a planned-but-
never-implemented libsecret credential store. That pin silently downgraded Avalonia's
transitive `0.92.0` dependency. Avalonia had been compiled against `0.92.0` which had
`Connection`. We removed the pin. Fixed.

Then the app stalled before the window appeared — a separate environment variable issue
on Jonny's end. Not our code. Moving on.

### The great Windows RDP chase

Jonny connected from Windows and got `ERRCONNECT_DNS_NAME_NOT_FOUND` — on a plain IP
address. On both an IP AND a hostname. wfreerdp worked fine with the same creds.

We added `freerdp_get_last_error` reporting first, so we'd at least see the specific
error code instead of a generic message. That confirmed DNS_NAME_NOT_FOUND exactly.

**Hypothesis 1: wrong settings offset.** The `SettingsOffset = 320` constant was
verified on Linux with a GCC-for-Linux build. Our Windows DLL was cross-compiled
with mingw-w64. The `rdpContext` struct layout might differ between the two targets.
We added `jabsco_get_settings()` to `dllmain.c` — a C function that does
`instance->context->settings` directly, letting the compiler resolve the correct offset
for whatever platform it's targeting. Added `-I` flags, fought through a cascade of
missing generated headers (`threads.h`, `winpr/config.h`, `freerdp/config.h`) — each
one its own small battle in the build script. Got the DLL built.

Still DNS_NAME_NOT_FOUND.

**Hypothesis 2: WSAStartup not called.** Our `DllMain` stub returned `TRUE` without
initializing Winsock. On Windows, every DLL that uses sockets must call `WSAStartup`.
WinPR's own DllMain would normally do this, but we override DllMain with our stub.
Added `WSAStartup(MAKEWORD(2, 2), &wsa)` in `DLL_PROCESS_ATTACH`. Rebuilt.

Still DNS_NAME_NOT_FOUND.

**Hypothesis 3: actual getaddrinfo broken in our DLL.** Added `jabsco_test_getaddrinfo`
— a function that calls `getaddrinfo` directly and returns the WSA error code. Wired it
up in C# to call it before `freerdp_connect`. If it failed, we'd get a WSA error number.
If it succeeded, the problem was somewhere inside FreeRDP's connection logic.

User got `EntryPointNotFoundException`. The DLL hadn't been rebuilt yet. Built it.
`jabsco_test_getaddrinfo` returned 0 — Winsock was fine. Settings keys were verified
against the actual `settings_keys.h` in the build cache — all correct.

Then Jonny ran it. **It worked.** RDP connected on Windows.

We never found the precise root cause — the combination of jabsco_get_settings
(fixing potential struct layout divergence) and WSAStartup (ensuring socket init) was
the fix. Most likely the struct offset was the primary issue; WSAStartup was defensive
correctness.

Cleaned up the diagnostic code: removed `TestGetAddrInfo` P/Invoke, removed
`SettingsOffset = 320` comment, switched `SettingsSetUInt32` → `SettingsSetUInt16` for
`ServerPort` (key 19 was always a uint16 key), added Linux fallback path so
`jabsco_get_settings` is only called on Windows.

### Everything else (fast)

**Hyper-V form:** Username/password fields added. VM GUID text box with "Enter GUID
manually…" sentinel at bottom of dropdown — selecting a real VM auto-populates the
GUID box (disabled), selecting the sentinel enables it for manual entry. Linux fallback
shows only the sentinel since WMI is Windows-only.

**macOS build task:** `mise run publish:mac` defaults to arm64. Pass `-- --universal`
to get a lipo'd fat binary (arm64+x64). The script publishes both, copies arm64 build
to output, then lipo-replaces every Mach-O file with a universal version. Cleans up
temp dirs.

**Single binary entry point:** Jabsco.Ui is now `Jabsco.exe`. `Program.cs` checks
`args.Length` — if args present, attach console on Windows (`AttachConsole(-1)`) and
run `CliEntry.RunAsync(args)`. If no args, launch Avalonia. `Jabsco.Cli` still exists
as a project (commands live there) but is no longer published separately. The
`publish:*` tasks were cleaned up to remove the redundant cli output.

**Feature flags:** `[feature]` section in `config.toml`. First flag: `hyperv = true`.
Defaults to `false` — the Hyper-V tab strip in the connection panel is hidden unless
explicitly enabled. Config is loaded once at app startup in `App.axaml.cs` and threaded
through `MainWindowViewModel` → `ConnectionPanelViewModel`.

**Token count:** After each agent run completes, the Session Chat header shows
`in 14.2k · out 1.3k` (accumulated across runs in the session). `Compact()` helper
formats < 1000 as plain integer, ≥ 1000 as `X.Xk`. Hidden until the first run ends.

**Tab styling:** Active tabs look "pressed in." `Border.tabUnit` wrapper handles the
visual — `Background="#D4D4D4"`, `BorderThickness="1,2,1,0"`, `BorderBrush="#B0B0B0"`,
`CornerRadius="8,8,0,0"`. The session panel gets a matching `BorderBrush="#D4D4D4"`
`BorderThickness="4,2,4,4"` frame so the active tab visually connects to the content.
Close buttons: `Foreground="#BBBBBB"` by default, `#444444` on hover, always
transparent background (removed the old red hover).

**Active tab bug fix:** `ShowConnectionPanel()` was setting `ActiveTab = null` without
first calling `ActiveTab.IsActive = false`. The previously-selected session tab would
stay pressed in even after navigating to Connections. One missing line.

**Connection panel theme:** Background changed to `#D4D4D4`. Form card backgrounds
lifted to `#EBEBEB`. Card borders `#C0C0C0`. Inner borders `#CACACA`. Blues → purple
`#7B2FBE` throughout (buttons, active RDP/Hyper-V tab strip).

### What's next / keep in mind

- **GDI and input offsets on Windows** (`GdiOffset = 264`, `InputOffset = 304`) were
  verified on Linux only, same as the settings offset that caused our whole chase. If
  frame capture or input breaks on Windows, that's where to look first. Consider adding
  `jabsco_get_gdi()` and `jabsco_get_input()` wrappers to the shim the same way we did
  for settings.

- **Hyper-V end-to-end test** — the VMConnect settings wiring is correct per FreeRDP
  source (`port 2179`, `VmConnectMode`, `NegotiateSecurityLayer=false`, etc.) but it's
  never been tested against a real VM. The first real test will tell us if the preconnect
  PDU flow works.

- **macOS `SettingsOffset`** — same story as Windows. The offset is Linux-verified. On
  macOS (arm64 or x64), the struct layout should match GCC conventions but it's
  unverified. If macOS RDP ever fails with DNS errors, check offsets first.

- **The "double tool execution" bug** — the HELOHELO ghost from a past session. The
  post-action delay probably masked it. Worth a dedicated investigation someday.

- **Config hot-reload** — config is currently loaded once at startup. If someone edits
  their config.toml mid-session (e.g. to enable hyperv), they have to restart. Could be
  worth a reload button or file watcher down the line.

This was a good one. We shipped.
