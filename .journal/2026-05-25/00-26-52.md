### History pane (bc80b99)

The side panel now has two tabs: Chat (💬 → now an SVG path) and History (◷).
Both highlight when active. The panel open/close is handled by `TogglePanelCommand`
on the `»` button and pull-tab; clicking a tab always opens the panel if closed.

**Stats block** — three rows at the top of the history pane:

- **Screenshots**: count of screenshots taken in the current/last run + estimated
  token cost. `EstimateImageTokens()` reads the PNG IHDR header directly (bytes
  16–19 = width, 20–23 = height), computes `w * h / 750`. Resets per prompt send.
- **Cached**: `cache_read_input_tokens` from the Anthropic API response. This was
  being silently discarded — now parsed into `TokenUsage.CachedInputTokens`, accumulated
  in `AgentLoop`, and surfaced on `AgentStats`. No new API calls; it was already in the
  response JSON.
- **System + Skills**: `provider.BuildSystemPrompt().Length / 4` — called on the live
  `ClaudeProvider` instance right after it's created. `BuildSystemPrompt()` was made
  `public`. No duplication of the prompt-building logic.

**Event log** — separate from `ChatItems`. Currently logs:
- `◆` token snapshot on run complete: `in X · out X · cached X · N steps · X.Xs`
- `⇄` control mode changes (from `OnControlModeChanged` partial)
- `!` errors

Extensible — new event types can be added by calling `HistoryItems.Add(new LogItem(...))`.

**Cancellation fix**: `ct.ThrowIfCancellationRequested()` in `AgentLoop` was throwing
an unhandled OCE that skipped the post-loop `FinalEvent`, so cancelled runs never got
stats. Changed to `if (ct.IsCancellationRequested) { stopped = UserCancel; break; }` —
all cancellation paths now go through the clean break, and `FinalEvent` is always
emitted. The consumer's `if (ct.IsCancellationRequested) break` was removed so it
actually processes the event.

Side effect: the pending action item on a cancelled run is now marked `Failure` (not
`Success`, which was a pre-existing bug).

`"— stopped —"` in chat is now added in the `FinalEvent` handler for `UserCancel`,
not in the catch block. Step/time-budget stops also show a `· step limit` / `· time limit`
suffix in the history log.

### SVG icons (bbfc6b4)

`src/Jabsco.Core/Icons.cs` — static class with three SVG path data constants
(Material Design, Apache 2.0 license). 24×24 viewBox.

- `Chat` — speech bubble, tail at bottom-right (horizontal mirror of the standard
  Material chat icon). Single closed path, no fill rule tricks needed.
- `History` — Material "history" icon (counter-clockwise arrow around a clock face).
  Two subpaths in one string.
- `Settings` — Material gear with `F1` prefix (Avalonia even-odd fill rule) to punch
  out the inner circle. Without `F1`, the hole fills solid.

In `SessionView.axaml`:
- Added `xmlns:core="using:Jabsco.Core"`.
- Replaced `TextBlock Text="💬/◷/⚙"` with `Path Data="{x:Static core:Icons.X}"`.
- `Fill="{Binding $parent[Button].Foreground}"` — the path colour is driven entirely
  by the button's `Foreground`, which is set in styles: `#9AB8D4` (inactive) and
  `#E8F4FF` (active, via `Button.strip-icon.active` style). No hardcoded colours on
  the path elements.
- `FillRule` attribute does NOT exist on Avalonia's `Path` — use the `F1` prefix in
  the path data string itself instead.

### Chat icon evolution

The chat icon went through a couple of iterations:
1. First try: speech bubble with three punched-out dots (`F1` even-odd, three circle
   subpaths). Jonny wanted simpler — no dots.
2. Second try: tail pointing right (horizontal) — looked like an arrow, not a bubble.
3. Final: same classic bubble shape as Material Design, tail at bottom-RIGHT. Achieved
   by mirroring the original path (negate all relative-x, flip arc sweep directions).
   Uses `F1`-free path (no inner cutouts needed).
